### LMS-001 · Scaffold `lms-web` (Next.js 16) - Status: DONE

`[Setup]` &nbsp;|&nbsp; Priority: **High** &nbsp;|&nbsp; Estimate: **2h**

#### 📖 User Story

> As a developer, I want a clean Next.js 16 project with all tooling configured, so I can start building features immediately without fighting setup.

#### ✅ Acceptance Criteria

1. Project bootstrapped with `create-next-app` — App Router, TypeScript, Tailwind, ESLint selected.
2. `shadcn/ui` initialized and at least Button, Card, Input components installed.
3. Prisma installed and `schema.prisma` created with initial models.
4. `DATABASE_URL` connected to Neon PostgreSQL; `prisma db push` runs without errors.
5. Project runs locally on `localhost:3000`.
6. `AGENTS.md` present (auto-generated by `create-next-app`) and updated with project context.
7. `.env.example` lists all required environment variables.

#### 🔧 Technical Notes

- Next.js 16.2 — Turbopack is on by default, no extra flags needed.
- React Compiler is stable in Next.js 16 — enable in `next.config.ts` via `reactCompiler: true`.
- Route protection uses `proxy.ts` (renamed from `middleware.ts` in Next.js 16).
- Neon serverless driver: `@neondatabase/serverless` for edge compatibility.

### LMS-002 · Scaffold `lms-realtime` (Bun + Express + Socket.io) - Status: DONE

`[Setup]` &nbsp;|&nbsp; Priority: **High** &nbsp;|&nbsp; Estimate: **2h**

#### 📖 User Story

> As a developer, I want a standalone Bun + Express + Socket.io server in its own repo, so real-time events can be developed and deployed independently from the Next.js app.

#### ✅ Acceptance Criteria

1. Repo initialized with `bun init`, TypeScript configured.
2. Express + Socket.io installed and server starts with `bun src/index.ts`.
3. CORS configured to allow connections from `localhost:3000` and the Vercel production domain.
4. A test client can connect via WebSocket and receive a `connected` confirmation event.
5. Health check endpoint `GET /health` returns `{ status: "ok" }`.
6. Upstash Redis connected via `ioredis`; a test ping succeeds.
7. `.env.example` lists: `PORT`, `CLIENT_URL`, `REDIS_URL`, `DATABASE_URL`.

#### 🔧 Technical Notes

- Bun has built-in TypeScript and `.env` — no `ts-node` or `dotenv` needed.
- Socket.io and ioredis are fully compatible with Bun 1.x.
- Use `socket.io-redis` adapter from the start — enables horizontal scaling later.
- `DATABASE_URL` is also needed here for saving quiz results back to PostgreSQL.

### LMS-004 · Authentication — Register, Login, Sessions - Status: DONE

`[Feature]` &nbsp;|&nbsp; Priority: **High** &nbsp;|&nbsp; Estimate: **5h**

#### 📖 User Story

> As a visitor, I want to register with my email and password and log in securely, so I can access my personalised LMS dashboard.

#### ✅ Acceptance Criteria

1. Register page collects: name, email, password, role (Student / Teacher).
2. Passwords are hashed with argon2 before storage.
3. Login page authenticates via NextAuth.js Credentials provider.
4. JWT session contains: `userId`, `email`, `role`.
5. Unauthenticated users are redirected to `/auth/login` from any protected route.
6. Form validation shows inline errors (empty fields, invalid email, weak password).
7. "Remember me" extends session to 30 days.

#### 🔧 Technical Notes

- NextAuth.js v5 (Auth.js) with Prisma adapter.
- In Next.js 16, route protection goes in `proxy.ts` (not `middleware.ts`).
- Password minimum 8 chars, at least one number — enforced with Zod on both client and server.
- Session token passed to `lms-realtime` on WebSocket handshake for identity verification.

### LMS-005 · Role-Based Access Control (RBAC) - Status: DONE

`[Feature]` &nbsp;|&nbsp; Priority: **High** &nbsp;|&nbsp; Estimate: **3h**

#### 📖 User Story

> As a platform admin, I want teachers and students to only access features relevant to their role, so the platform stays secure and uncluttered.

#### ✅ Acceptance Criteria

1. Three roles enforced: `STUDENT`, `TEACHER`, `ADMIN`.
2. Teachers can create, edit, and delete their own courses.
3. Students can only enroll in and view courses.
4. Admin role can manage all users and all courses.
5. Attempting to access a forbidden route returns a styled 403 page.
6. Role is displayed in the user's profile dropdown.

#### 🔧 Technical Notes

- Role checked in `proxy.ts` using the session token.
- Server Actions and API Route Handlers re-validate role server-side — never trust the client.
- Create a `withRole(role)` wrapper for page-level protection.
- `lms-realtime` also verifies role from the JWT on socket connection for teacher-only events.

### LMS-011 · Quiz Builder (Teacher) - Status: DONE

#### 📖 User Story

> As a teacher, I want to create quizzes with multiple-choice and true/false questions attached to a lesson, so I can assess student understanding.

#### ✅ Acceptance Criteria

1. Teacher can create a quiz linked to a specific lesson.
2. Question types supported: multiple-choice (1 correct answer), true/false.
3. Each question has a point value (default: 1).

### LMS-012 · Quiz Attempt & Auto-Grading (Student) - Status: DONE

`[Feature]` &nbsp;|&nbsp; Priority: **High** &nbsp;|&nbsp; Estimate: **5h**

#### 📖 User Story

> As a student, I want to take a quiz and immediately see my score, so I know how well I understood the material.

#### ✅ Acceptance Criteria

1. Student sees a "Take Quiz" button on the lesson page.
2. Quiz renders one question per screen with a progress indicator.
3. Timer counts down if a time limit is set; auto-submits on expiry.
4. On submission, score is calculated server-side (never trust the client).
5. Results page shows: score, passed/failed, correct answers highlighted.
6. Student can retake the quiz (each attempt stored separately).

#### 🔧 Technical Notes

- `QuizAttempt` stores `(userId, quizId, score, startedAt, submittedAt)`.
- `AttemptAnswer` stores each selected answer per attempt.
- Grading happens in a Server Action — loop answers, check `isCorrect`, sum points.
- Timer: `useEffect` + `setInterval` client-side, auto-calls submit Server Action on expiry.

### LMS-015 · Live Notifications System

`[Feature]` &nbsp;|&nbsp; Priority: **High** &nbsp;|&nbsp; Estimate: **5h**

#### 📖 User Story

> As a student, I want to receive instant notifications when I receive a grade or when a teacher publishes a new lesson, so I'm always up to date without refreshing the page.

#### ✅ Acceptance Criteria

1. Notification bell icon in the top nav shows an unread count badge.
2. Clicking the bell opens a dropdown list of recent notifications.
3. Notification types: new grade received, new lesson published, enrollment confirmed.
4. Notifications arrive in real-time without a page refresh.
5. Notifications are persisted in the DB and survive page refreshes.
6. Marking all as read clears the badge.

#### 🔧 Technical Notes

- Flow: Next.js Server Action saves grade → publishes `notification:new` to Upstash Redis → Socket.io server picks up → emits to `user:{userId}` room.
- Each user joins a personal room on connect: `socket.join(\`user:${userId}\`)`.
- Identity verified on handshake using the NextAuth JWT passed as a socket `auth` token.
- `Notification` model in Prisma: `(userId, type, message, readAt, createdAt)`.
- `useNotifications` custom hook manages state + Socket.io listener on the client.

### LMS-016 · Live Quiz Session (Teacher Hosts)

`[Feature]` &nbsp;|&nbsp; Priority: **High** &nbsp;|&nbsp; Estimate: **8h**

#### 📖 User Story

> As a teacher, I want to host a live quiz session where all students answer simultaneously and I can see results update in real-time, like a Kahoot-style experience.

#### ✅ Acceptance Criteria

1. Teacher can start a "Live Session" for any published quiz.
2. A shareable 6-character session code is generated (e.g., `ABC123`).
3. Students enter the code to join the session lobby and see a waiting screen.
4. Teacher controls question pace — "Next Question" advances all participants simultaneously.
5. Students see a countdown timer per question (configurable per quiz).
6. Teacher's screen shows a live leaderboard updating after each answer.
7. Session ends when teacher clicks "Finish"; final scores are saved to `QuizAttempt` in DB.
8. Disconnected students can rejoin using the same session code.

#### 🔧 Technical Notes

- Socket.io rooms: `session:{sessionCode}` for students, `teacher:{sessionCode}` for the host.
- Full session state (current question index, scores per student) stored in a Redis hash — survives server restarts.
- Events: `session:join`, `session:start`, `question:next`, `answer:submit`, `leaderboard:update`, `session:end`.
- Final scores written to `QuizAttempt` by `lms-realtime` directly using Prisma Client on `session:end`.
- Session code expiry: set a Redis TTL of 24 hours on the session hash.
